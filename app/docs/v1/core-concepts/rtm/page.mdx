# Requirements Traceability Matrix (RTM)

The Requirements Traceability Matrix (RTM) is the backbone of every Qlitz project. It maps business requirements to test cases, making test coverage objective rather than estimated.

## Why traceability matters

Without traceability, coverage is a guess. Teams know how many tests pass but not what those tests actually verify. The RTM answers the questions that matter:

- Is requirement X covered by at least one test?
- Which requirements have no automated coverage?
- If a test fails, which requirement is at risk?
- Is the application ready to release against the committed requirements?

## Structure of the RTM

## Adding requirements

Requirements can be added in three ways:

**Manually** — click **Add Requirement** in the RTM tab and fill in the fields.

**Bulk import** — paste requirements in plain text or upload a CSV. Qlitz parses titles and optional acceptance criteria automatically.

**From the Canvas** — when you generate a framework, test stubs are linked back to RTM requirements. The RTM updates to reflect which requirements now have generated test cases.

## Coverage calculation

Coverage is calculated per requirement based on linked test results from the most recent test run:

- **Covered** — at least one linked test passed in the latest run
- **Partial** — linked tests exist but some failed or were skipped
- **Not Covered** — no linked tests exist, or none have been executed

This calculation flows directly into the **Coverage** tab, the **Readiness** score, and the **Release** readiness assessment.

## RTM and releases

When you create a release, Qlitz scopes the readiness calculation to the requirements marked as in-scope for that release window. This means a release can be assessed against a subset of requirements — for example, the requirements scheduled for a specific sprint.
