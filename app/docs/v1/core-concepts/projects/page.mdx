# Projects

A Project is the top-level container in Qlitz. Every artifact — requirements, test cases, generated frameworks, execution results, and releases — belongs to a project.

## What a project represents

A project maps one-to-one with an **application under test**. If your organisation has a customer portal, an admin dashboard, and a mobile API, each gets its own Qlitz project. This separation keeps requirements, coverage, and release history clean and scoped.

## Creating a project

1. Click **New Project** in the global left sidebar
2. Enter a project name (required) and description (optional)
3. Set the base URL of the application under test
4. Click **Create**

The project is immediately available. Start with the RTM tab to define your requirements before moving to the Canvas to generate your first framework.

## Project data model

Behind the scenes, each project stores data across two layers:

- **Database** — project metadata, release records, RTM requirements, and test case definitions are stored in PostgreSQL via Prisma
- **File store** — execution results, auto-heal events, replay recordings, and generated framework archives are stored as JSON files scoped to the project ID

This hybrid model keeps structured data queryable while keeping large execution artifacts lightweight and portable.
